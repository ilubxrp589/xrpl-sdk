# Contributing

Thank you for helping. Bug reports, fixes, documentation and new features are
all welcome. This page says how the project works so that a change can be
reviewed and merged quickly.

**Security issues are not reported here.** Follow [SECURITY.md](SECURITY.md)
(GitHub's private vulnerability reporting).

## The rules every change keeps

1. **`rippled` decides.** Anything that must agree with the ledger (encoding,
   signing, hashes, IDs, fees, what is refused) is checked against `rippled`
   itself: a recorded answer from a real server, `rippled`'s `simulate`, or
   its source, cited in the test. [docs/PARITY.md](docs/PARITY.md) lists what
   is checked, and [docs/TESTING.md](docs/TESTING.md) says where each test's
   data comes from. A claim that cannot be checked is not made.
2. **No panics in library code.** No `unwrap`, `expect`, unchecked indexing,
   narrowing `as` casts or `unsafe`; the workspace lints enforce it. Test
   modules opt out explicitly.
3. **Secrets stay secret.** Seeds, keys, phrases and URLs (which may carry an
   API key) never reach a log, an error message or `Debug` output.
4. **No silent changes.** The codec refuses what `rippled` refuses instead
   of changing the transaction, and a function that cannot know an outcome
   says so instead of guessing.
5. **Documented and tested.** Every public item has a doc comment (most with
   an example that compiles and runs), and every change has a test.

## Before you open a pull request

```bash
cargo test --workspace
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo fmt --check
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --all-features
```

CI runs these on Linux, macOS and Windows, plus the minimum supported Rust
versions (1.85 for `halcyon-xrpl-core`, 1.88 for the rest), the `no_std` and
`wasm32` builds (with the wasm tests in Node.js), the docs as docs.rs builds
them, `cargo package`, a SemVer check against the latest release, a security
audit of the dependencies and a short fuzzing run of every target.

Add a line to [CHANGELOG.md](CHANGELOG.md) under **Unreleased**: what changed
for someone using the SDK, in plain words. A breaking change says so and
says how to update.

## Commits

One logical change per commit, with a message of the form
`feat(crate): what it adds`, `fix(crate): what was wrong`, or
`docs: …` / `test: …` / `ci: …`. The body says why, and how it was checked.

## Generated code

The transaction models, ledger entry types and word lists are generated by
the scripts in `crates/xrpl-core/scripts/` from `rippled`'s definitions and
published standards. Change the script and regenerate; do not edit the
generated files by hand.
